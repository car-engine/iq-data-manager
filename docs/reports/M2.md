## Decisions made

- D11, scanner folder rules (closes O4).
- D12, gap rule (closes O5).
- D13, last file without IQ data (closes O24). The user decided this after reading

The user chose the proposed default for all four questions. D11 also records the
defaults that the approved plan stated without a question: leading-zero folder names
are errors, extensions match in any letter case, symbolic links are unrecognised,
and an empty channel folder is a channel with no files.

## Changes from the plan

- **Two code commits instead of four.** Detection, listing, gaps and the channel
  check are one module, so they went into one commit (`6402af7`) with their tests.
- **`check_channel()` instead of `check_file_sizes()`.** The function also reports
  channels with no files and files that are too close together, so the planned name
  was too narrow. It takes the file duration from the `ChannelScan`.
- **Unrecognised folders end with `/`** in `ScanResult.unrecognised`, for example
  `logs/` and `0/nested/`. A symbolic link has no trailing `/`.
- **A failure to list a channel folder** (an `OSError`) becomes one of the
  `ScanError` problems. The plan named only a missing folder and a path that is a
  file.
- **The stat-count test patches `os.stat` and `os.lstat`.** `Path.stat` calls
  `os.stat`, so the planned separate patch of `Path.stat` was unnecessary. The test
  allows at most 5 calls for 600 files.

## Untested or not testable here

- **Scanning on the NAS.** Agents may not access network paths. The scanner reads
  only directory listings, so an SMB share should cost one listing per folder. The
  user can time a scan of a real NAS recording folder from a Python prompt in the
  venv.
- **Symbolic links.** This account cannot create them, so
  `test_symbolic_links_are_unrecognised` skips. Run it from an account with the
  "Create symbolic links" privilege, or with Developer Mode on.
- **Directory junctions.** No test creates one. The code checks
  `DirEntry.is_junction()` (Python 3.12) and lists a junction as unrecognised.
- **Real recordings.** The tests use synthetic fixtures only.

## Issues found in self-review

1. **Stray file in the repository root.** A malformed shell command created an empty
   file, `fixtures_out_mut_conftest.py`. The command then waited for input until
   the agent stopped it. The file is untracked and is not in any commit. Agents may
   not delete files, so it is in the list below.
2. **An empty last file counted as a short last file.** A 0-byte last file gave an
   info finding under D3, although it could mean that a write failed. Recorded as
   O24. The user decided that a last file without IQ data is an error. The user
   wrote "size < header size". The rule uses `size <= header_bytes`, because with no
   header a 0-byte file is not smaller than the header. Fixed by D13, with 6 new
   tests.
3. **Timestamps are floats.** Stems with more than about 7 decimal places lose
   precision at current Unix times. Two such stems could parse to the same value
   and be reported as a duplicate. No current recorder writes such names. Left
   unchanged.
4. **`check_channel()` uses the duration given to the scan.** If the user changes
   the file duration in the Log tab, Milestone 3 must rescan or rebuild the
   `ChannelScan` before it checks the channel again.
5. **A short last file need not hold whole samples.** With `header_bytes = 0`, a
   1-byte last file is information under D3 and D13, although 1 byte is not one
   complex `int16` sample. Left unchanged and reported here.
6. **`make_fixtures.py` allows `int32`.** D1 allows only `int8`, `int16` and
   `float32`. The fixture tool is not part of the app, and no test uses `int32` with
   the scanner. Left unchanged and reported here.
