**Check before delete cannot read through a share of the same PC.** It failed with
`[WinError 87] The parameter is incorrect` on every file. A probe
(`dev/review/uncached_probe.py`, reads only) opened and read one file with
`FILE_FLAG_NO_BUFFERING`, as [uncached.py](../../src/iqdm/transfer/uncached.py) does:

- through the share: every read failed, at 64 KiB, 1 MiB, 4 MiB and 8 MiB per read;
- the same file through its local path: passed;
- another file on the same disk (D:), not through the share: passed.

So the failure comes from a Windows PC serving a share to itself, and the app's reader
and the disk are not at fault. The real NAS is a separate server. In the field test of
2026-10-05 its Check before delete passed for set B (many 64 KB files) and set D (a
short last file), and the deletes that followed passed. The failure is safe: the check
fails, and Delete laptop copy stays disabled.

### Untested or not testable here

- **D75 on the NAS.** The identity comes from the volume serial number and the file
  ID that the NAS reports over SMB. Tested with junctions and hard links on a local
  NTFS disk only. A laptop disk and the NAS are two volumes, so archives from a laptop
  compare as different files whatever the NAS reports. A NAS that reports file ID 0
  would make two NAS folders compare as "unknown", and the app would refuse transfers
  between them. Not measured: the cost of one more `stat` per file on each side during
  verification, over SMB.
- **D76 across two PCs.** Tested on one database file and one PC.
- **Check before delete through a share of the same PC** fails (see above). Not a
  case the app supports; noted for anyone who tests on one PC.
