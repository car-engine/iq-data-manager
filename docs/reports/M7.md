### Code that creates or overwrites a file

Milestone 7 added no `.unlink()`, `.rmdir()`, `os.replace` or `shutil` call. The
architecture test now applies the file-writing rules to `legacy.py` and
`db/legacy.py` too.

| Code | What it writes | Guard |
| --- | --- | --- |
| `legacy.main()` with `connection.create_database()` | A new database | `create_database()` refuses a path that exists; the command also refuses the legacy file itself |
| `legacy.main()`, report | `<new database>.report.txt` | Checked before anything is written; `open("x")` |
| `db/legacy.read_legacy_rows()` | Nothing | The legacy file is opened with `mode=ro` |
| Settings tab, "New database..." | A new database | Save dialog without the replace prompt; the tab refuses an existing file, asks Yes/No (default No), and `create_database()` refuses again |
| `build/iqdm.spec`, after `COLLECT` | Three files next to the programs | A new output folder per build (D8); `open("xb")` |
| `repository.update_channels_from_folder()` | Database rows only | Called only by Check archive, for channels without counts |

## Changes from the plan

- **O20 is not done.** The plan froze the version 1 schema at the end only if the
  field test showed no schema change and the real catalogue was about to be made.
  The real catalogue waits for Milestone 8 (D72), so O20 moved there.
- **The final build moved to Milestone 8.** `dist/m7-4`, built from `main`, is the
  build for the second visit to the NAS. The release build comes from `main` with version 1.0.0.
- **`copy-check --workers` needed no code.** The option already existed; the plan
  had listed it as new.
- **The D2 row comes from one function.** `repository.insert_in_place_check()` now
  writes it for the Log tab and for the import. The plan did not name this change.
- **`update_channel_counts()` was replaced** by `update_channels_from_folder()`, which
  also sets times and derives the recording's envelope again (D71).
- **The packaged import and the defaults-file check were run by the user.** The
  safety hook blocks an agent's shell command that holds a UNC path, so the plan's
  build check of `migrate-legacy` could not run here.

## Issues found in self-review

1. **The first test run of D70 hung.** A window test left settings unsaved; pytest-qt
   closed the window at teardown, which opened the real question with nobody to
   answer it. The window tests now stub that question by default, and the dialog is
   tested separately with its real buttons.
2. **`migrate-legacy` ran into its description** in the console program's command
   list. Fixed in `b1bdccc`.
3. **Two shell commands were blocked by the safety hook** for UNC text: the packaged
   import check and the checklist substitution check. Both were reported and not
   worked around.
4. **The field test's timing rule for the cache was wrong for a fast link.** It
   assumed about 110 MB/s; on 10 GbE, reads from the NAS and from memory both take a
   few seconds. The second visit uses `netstat -e` instead.
5. **The `copy-check` check column looked like a NAS read speed.** It reads through
   the PC's cache. The output now says so (`80c408d`).
6. **The field-test logs hold the real NAS address.** They stay in
   `dist/m7-2/IQDataManager/field-test/`, outside git; the reports use `\\nas\share`.
