## Summary

No finding puts a recording at risk. The data-safety paths of 1.1 behave as D80 and
D83 describe: the recorder's logs reach Delete laptop copy only through the
manifest, so the per-file checks of D52, D55 and D75 apply to them.

Three findings should be fixed in 1.1.1:

1. **A database error in the queue's Check before delete marks a passed archive ✗
   Failed** (finding 1). D85 exists to prevent this display.
2. **A template imported after the scan replaces values from the recorder's log and
   keeps the log's italics and tooltip on them** (finding 2). The checklist then names
   log values that the form no longer holds. SPEC section 6 says that log values
   replace template values.
3. **The log fills "USRP Gain", and the catalogue spells it "USRP gain"**, so every
   scan of a recorder folder shows an information line about the spelling (finding 3).
   The user reported this one.

Six findings are minor (findings 4 to 9).

The user's answers of 2026-10-22 close the field checks of 1.1:

- Every pending check of version 1.1 passed with the real NAS and real recordings:
  the queue with Pause and Start part-way through a large archive; a recorder
  recording logged, archived with its log files, checked before delete and deleted
  from the laptop; several real folders logged in a row with a template kept in a
  shared folder; the Viewer's tick-box filters; the 1.1 screens in dark mode.
- O22 is done: a backup of the catalogue runs outside the app. The team no longer
  uses the legacy logging scripts.
- Not seen in use: slow copies of small files (O37), the Log tab hanging on a typed
  path, and a check left unfinished after a network error (O40).
- Only the team's recorder build writes the logs that D82 reads.

Recommendation: fix findings 1, 2 and 3 in 1.1.1, with the small minor findings 4, 5,
6, 8 and 9. Finding 2 needs a decision from the user on which value wins (see the
finding).

## Findings

Severities: **fix in 1.1.1**, **should fix later**, **minor**.

### 1. Fix in 1.1.1: a database error in the queue's Check before delete shows a passed archive as ✗ Failed

[transferqueue.py:403-416](../../src/iqdm/transferqueue.py#L403-L416),
[transfer_tab.py:1634-1645](../../src/iqdm/gui/transfer_tab.py#L1634-L1645).

`run_item()` runs Check before delete after an archive passed, and catches
`DeleteRefused`, `TransferError` and `OSError` from it. Each of those gives the D85
state "Archived, check needed". `check_before_delete()` also writes two rows with
`write_transaction()`, and reads the archive with `open_db()`. Those raise
`DatabaseBusyError` after the retries of D7, or another `DatabaseError`. Neither is
an `OSError`, so the exception leaves `run_item()`. `TransferTab._queue_item_failed()`
turns every exception it does not name into `QueueState.FAILED`.

Failure: two PCs use the catalogue on the NAS. One PC's queue archives a recording,
and the archive passes. The recording now points at the NAS copy. The check's first
write meets a lock that lasts past the retries (1 s and 2 s). The queue shows "✗
Failed" with "The database is in use by someone else…", and the summary is red. The
user takes the archive for failed. The manual test of 2026-10-22 (O49) found this
same misreading, and D85 changed the display for that case.

Confirmed by `test_probe_db_error_in_check_before_delete_escapes_run_item`:
`check_before_delete` replaced by a function that raises `DatabaseBusyError`;
`run_item()` raises it, and the recording is `archived`. The mapping to Failed was
read in `_queue_item_failed()`. The existing test
`test_a_check_that_cannot_run_is_check_needed` covers `OSError` and `DeleteRefused`
only.

### 2. Fix in 1.1.1: a template imported after the scan replaces the log's values and keeps their "from the log" mark

[log_tab.py:1417-1447](../../src/iqdm/gui/log_tab.py#L1417-L1447),
[log_tab.py:737-770](../../src/iqdm/gui/log_tab.py#L737-L770),
[SPEC.md section 6](../SPEC.md) ("Log values replace kept and template values").

D82 fills values from the recorder's log once per folder, after the scan, and marks
fc and fs in italics with the tooltip "Filled in from the recorder's log". Import
template... after that scan writes the template's band and fc into the channel rows
with `setText()`, which does not clear the row's `fc_log` flag. The template's RF
chain rows replace every row of the form, the log's "USRP Gain", "Clock reference"
and "USRP" rows among them. `_log_filled`, which feeds the checklist line, does not
change.

Failure: a recorder folder at 300 MHz is scanned, and fc shows "300" in italics. The
user then imports a template holding fc 145.8 MHz for channel 0 and an Antenna row.
Channel 0 then shows "145.8" in italics with the tooltip "Filled in from the
recorder's log. Type a value to replace it." The RF chain holds only "Antenna". The
checklist still says "Filled in from the recorder's log: sample type int16, fc of
channel 0, fs of channel 0, USRP Gain, Clock reference, USRP." Saving stores 145.8
MHz without the measured gain. The same happens with kept values only when the
template is imported before the scan, which matches the SPEC; the order of the two
actions decides the result.

Confirmed by `test_probe_template_after_scan_keeps_the_log_mark`.

Decision for the user: the SPEC rule says that the log wins. A fix in that direction
keeps the values the log filled for this folder when a template is imported after the
scan, and names the template fields that were not used on the message line. The
other direction lets the template win and clears the log's mark and its entries in
the checklist line.

### 3. Fix in 1.1.1: the log's "USRP Gain" against "USRP gain" in the catalogue

[recorderlog.py:32](../../src/iqdm/recorderlog.py#L32),
[entry.py:858-869](../../src/iqdm/entry.py#L858-L869).

`recorderlog.GAIN_PARAM` is `"USRP Gain"`. The real catalogue spells the parameter
"USRP gain". `entry._param_consistency_items()` adds an information line for every
name typed with another spelling than the stored one: "USRP Gain will be saved as
USRP gain, the spelling already in use." The save stores "USRP gain", so the data is
right. The line shows on every scan of a recorder folder.

Confirmed by the user (report of 2026-10-22) and by reading the code. The other two
names the log fills, "Clock reference" and "USRP", can meet the same line if the
catalogue holds another spelling of them. D82, SPEC section 6, the user guide and the
1.1.0 release notes name "USRP Gain".

### 5. Minor: the Pause question promises more than a pause during Check before delete gives

[transfer_tab.py:80-84](../../src/iqdm/gui/transfer_tab.py#L80-L84),
[USER_GUIDE.md](../USER_GUIDE.md) section on the queue, step 5.

The question says "Start continues with that item and does not copy them again."
When Pause comes while the queue runs Check before delete after an archive, the
check stops, and the item becomes "ⓘ Archived, check needed" (D85). Start skips that
item. The user must run Check before delete in the form. Step 5 of the guide says the
same as the question. Confirmed by reading `run_item()` and the existing test
`test_a_stopped_check_before_delete_is_check_needed`.

### 6. Minor: after Edit, a later Add to queue goes to the edited item's old place

[transfer_tab.py:1437-1463](../../src/iqdm/gui/transfer_tab.py#L1437-L1463),
[transfer_tab.py:1739-1750](../../src/iqdm/gui/transfer_tab.py#L1739-L1750).

Edit stores the item's position in `_edit_position`. Only Add to queue and
`_put_back_edit()` reset it. If the user drops the edit, for example by loading
another recording into the form, the next Add to queue inserts at that old position.
Failure: queue [recording 1, recording 2]; Edit recording 1; load recording 3,
preview it and click Add to queue. The queue becomes [3, 2]; the user expects
[2, 3]. Confirmed by `test_probe_an_edit_not_put_back_moves_a_later_item_to_its_place`.
Nothing runs out of turn without the user seeing the order in the table.

### 7. Minor: export replaces a file named `<template>.new` without a question

[templates.py:468-473](../../src/iqdm/templates.py#L468-L473).

`write_template()` writes `<name>.toml.new` with `write_text()`, which replaces an
existing file of that name, then renames it over the chosen file. The tab asks before
it replaces the chosen file, but not about the `.new` file. Failure: a shared
template folder holds `USRP.toml.new` from someone else; exporting `USRP.toml`
replaces it, and its content is gone. Confirmed by
`test_probe_write_template_replaces_a_dot_new_file`. The same pattern exists for
`config.toml.new` since Milestone 3a, inside `%APPDATA%`. The templates report lists
the `.new` file in its table "Code that creates or overwrites a file" without this
case.

### 8. Minor: a kept "USRP" row of a channel the new folder lacks stops the log's "USRP" row

[log_tab.py:1041-1045](../../src/iqdm/gui/log_tab.py#L1041-L1045),
[recorderlog.py:294-299](../../src/iqdm/recorderlog.py#L294-L299).

### 10. Fix in 1.1.1: a paused queue item can also be finished with the form's Run

[transfer_tab.py:2033-2041](../../src/iqdm/gui/transfer_tab.py#L2033-L2041),
[transfer_tab.py:1883-1889](../../src/iqdm/gui/transfer_tab.py#L1883-L1889).

Reported by the user on 2026-10-22, after the first version of this report. The form
enables Run whenever its preview passed and matches the form. A queue item added
from the form leaves that preview in place, so after Pause the button reads "Run
archive" or "Run copy" again. Resume under "Unfinished transfers" offers a third way,
because the paused item's transfer row is listed there. Neither knows about the queue
item, which stays "Paused".

Failure, archive: queue an archive from the form, Start, Pause part-way. Click "Run
archive": the archive passes and the recording points at the NAS copy, but no Check
before delete runs. The queue item still shows "Paused". Start then marks it "✗ Not
started: The recording is already archived. The destination is the source folder.
Choose another folder." and the summary reads "Queue finished. 1 not started."

Failure, copy: the same with a copy. Start then runs a second copy that copies no
file and records a second passed transfer.

No data is at risk. Run uses the preview made before the queue ran, but the copier
skips a destination file with the right size and refuses one with another size
([copier.py:167-171](../../src/iqdm/transfer/copier.py#L167-L171)).

Confirmed by `dev/review-1.1/test_probe_pause_run.py` (2 tests): after the pause Run
is enabled, and the results are as above.

## Checked and found consistent

- **Side files and Delete laptop copy (D83).** `Selection.files` adds the side files
  after the channels' files ([selection.py:79-94](../../src/iqdm/transfer/selection.py#L79-L94)).
  Their `timestamp` is `None`; no reader of `Selection.files` uses the timestamp
  (`movecopy.py`, `operations.py`, `pathcheck.py`). The destination check treats a
  side file as any target: same name and size counts as copied (D51), another size is
  refused ([pathcheck.py:331-367](../../src/iqdm/transfer/pathcheck.py#L331-L367)).
  `delete.py` did not change in 1.1. It deletes only `manifest.files`, each after the
  size, regular-file, inside-the-folder and file-identity checks, and removes only
  folders that held listed files and are empty. A laptop log that changed after the
  archive is kept with "The laptop file changed after the copy." `compare_with_laptop`
  and Check archive compare the channels only, as D83 says.
- **No path replaces an existing file** in the 1.1 transfer code: the copier still
  writes `.partial` and renames only to a free name. The one 1.1 path that replaces a
  file is `write_template()` (finding 7 covers its `.new` file).
- **The queue (D81, D85).** The tab stays busy between items: `is_busy` includes
  `_queue_running`, and `_end()` emits `busy_changed(is_busy)`. Pause cancels the
  running task between chunks; a paused copy continues with a new preview that skips
  the copied files. Closing the window while the queue runs stops it with
  `stop(ask=False)` and waits for the worker. Repeats are refused as D81 says. Edit is
  disabled for "Archived, check needed", and Clear finished keeps those items. A
  failed preview gives "Not started", and the queue moves on.
- **The Log tab.** A rescan of the same folder does not fill from the log again
  (`_log_applied_for`). A new folder clears it, so the log fills again. Clear form
  resets every field and the log state. Edit mode never fills from the log. Kept
  values (D79) before the scan give way to log values, as the SPEC says. Message
  states (D84) follow the theme.
- **The recorder's logs.** `read_originals.py` over the two original folders in
  `recorder/` gave the values of the cleaned examples: channels 0 and 1 at 300 and
  433 MHz, 50 MHz, gain 30 dB, `sc16`, GPSDO, X310 + UBX, 540 files written; and for
  the second folder one channel, internal clock from the PC clock, and check verdict
  PASS. Made-up variants: a `log.txt` with free text fills nothing and gives no line;
  a command line with `--channels a,b` or `--freq 300MHz` gives one line, "The
  recorder's log could not be used…"; a restart takes the later frequency; a log cut
  off before the channel blocks takes fc, fs and gain from its command line. No
  variant raised an exception.
- **Viewer tick-box filters (D78).** Several sites, projects and bands become `IN
  (…)` with one parameter per value; "No project" joins the projects with `OR`; the
  band compares with `COLLATE NOCASE`. Ticks stay on the same data when the lists
  reload. Edit entry, Archive / copy and Open folder need exactly one selected row;
  Add to queue needs one or more.
- **Frozen schema (D77).** `test_the_frozen_schema_is_the_released_one` checks the
  hash of `v1.sql`. `test_schema_sql_is_not_edited_in_place_while_the_version_is_1`
  compares every statement while `LATEST_VERSION` is 1. A comment inside a `CREATE`
  statement is part of its text, so editing one fails that test; the test's
  docstring says only comments outside statements may change, which agrees.
- **Visible text.** `tests/test_user_text.py` covers the template dialog and
  messages, the queue texts, the recorder-log lines, the side-file preview line and
  the kept-fields note. Apart from findings 4 and 5, the new texts read plainly.
- **Documents.** SPEC.md names D77 to D85 and states their current rules. The user
  guide and the 1.1.0 release notes match the labels on screen, apart from finding 5.
  The 1.1 reports update the table of code that deletes or overwrites a file for D80
  and D83.

## Points a new maintainer would miss

- **The order of template import and scan decides which values the form holds**
  (finding 2). Until it is fixed, the SPEC rule holds only for a template imported
  before the scan.
- **`run_item()` passes unknown exceptions to the tab, and the tab shows them as
  Failed.** Any new step after a passed archive must turn its errors into "Archived,
  check needed".
- **Values from the log carry their mark in `_ChannelRow.fc_log` and `fs_log`.** Any
  code that writes those fields without `textEdited` must set or clear the flags
  itself.
- **The review probes import fixtures from `tests/` by path** (`sys.path.insert` in
  the probe files). They show how to reuse the suite's fixtures in a throwaway test
  under `dev/`.
