## Untested or not testable here

- **A real mapped network drive.** Agents may not map drives. The tests replace
  `WNetGetConnectionW` with a fake resolver. The user can map a NAS share, choose a
  folder on it in the Log tab and check that "Storage root" shows the UNC root.
- **Scanning and saving on the NAS.** Agents may not access network paths. O21 still
  covers the database part.
- **The tab by eye.** The agent rendered the tab offscreen to an image and compared
  it with `docs/mockup/mockup_log.png`. The layout matches. Keyboard use, the folder
  dialog and real window behaviour are untested.
- **Edit mode for a folder on another laptop.** A rescan of a path that this PC cannot
  reach fails with a scan error, and saving without a rescan still works. Only the
  local case is tested.

## Issues found in self-review

1. **Parameter rows of a removed channel blocked the save.** In the first build, the
   rows of a channel that a rescan no longer found stayed in the RF chain table. The
   checklist reported each as "channel N is not in this recording", so the user had
   to remove the rows by hand before the D16 dialog appeared. Fixed by D20 in
   `c02a09d`, after the user's decision.
2. **The safety hook blocked two shell commands.** Both carried file content with
   backslash pairs that look like UNC paths: a heredoc for `DECISIONS.md` and a
   Python patch for the `--config` help text. The agent then made the same changes
   with the Edit tool. The hook checks only shell command text. A note for agents in
   `STATUS.md` now says to write file content with the Write and Edit tools. The
   agent also proposed a narrower pattern for the hook, and the user applied it. It
   matches a UNC path only at the start of a word. It passed 10 test strings,
   including an escaped UNC path inside `python -c`.
3. **The smoke test left a quit behind for later tests.** `main(["--smoke-test"])`
   runs the shared test `QApplication`. Its window closes after the event loop
   ends, and with `quitOnLastWindowClosed` on that close starts another quit. Later
   tests then received no signals from worker threads, and 24 Log tab tests timed
   out in the full run. The `smoke_app` fixture turns the setting off during the
   smoke tests. The app code is unchanged. In a real run the process exits after
   the smoke test, so the extra quit has no effect.
4. **`ruff format` changed lines outside the scope.** It rewrapped 4 existing calls in
   `test_repository.py`. 3 were restored before the commit. 1 went into `0c54c0b`
   and was restored in `98a7cca`. Five files on `main` are not in `ruff format`
   style. The project checks only `ruff check`, so they stay unchanged.
5. **A file written outside the repository and the scratchpad.** A probe script,
   `claude_pw.py`, went to the user's temporary folder (`%TEMP%`) by mistake. It
   checked `PureWindowsPath` behaviour and wrote nothing else. Listed below for
   removal.
6. **Read-only fields did not look read-only.** Start, end, storage root, relative
   path and archive state had the normal background. The user raised the same point
   after the first manual test. Fixed in `bd9d548`: they now have a grey background
   and a tooltip, as does the folder field in edit mode.
7. **"1 files differ" in a scanner finding.** `check_channel()` in
   [scanner.py](../../src/iqdm/scan/scanner.py) (Milestone 2) writes "1 files differ
   from the expected size". The manual test set shows it in
   `05_wrong_size_middle`. Left unchanged, because the scanner is outside this
   milestone's scope.
8. **`ruff format` changed `repository.py` again.** The agent ran it on all of
   `src/iqdm` and it rewrapped 2 calls in `repository.py`. Both were restored with the
   Edit tool before commit `8539616`, which does not touch that file.
9. **An empty channel also gets an fs to-do line.** In `10_empty_channel_folder`, the
   error "channel 2 has no data files" comes with "Enter fs (MHz) for channel 2".
   Entering fs cannot fix that channel. Left unchanged; it does not allow a wrong
   save.
10. **Wrong sample type gives a plausible fs.** With the default `int16`, folder `06`
    (`int8` with a 64-byte header) saves with fs 516 Hz, and folder `12` (`float32`)
    with fs 2 kHz. Only the information line that names the sample type and header
    shows it. This is the limit of D21 that the user accepted.
11. **`ruff format` reformatted files outside the change a third time.** Running it on
    all of `tests` rewrapped calls in `test_connection.py`, `test_make_fixtures.py`,
    `test_repository.py` and `test_timeutil_models.py`. All were restored with the
    Edit tool before commit `bd9d548`.
12. **One append through the shell.** The agent appended the time helpers to
    `timeutil.py` with `cat >>`, against its own note in `STATUS.md`. The text held no
    blocked words, and the result is correct.
13. **fs typed in the old MHz form is now read as Hz.** `0.001` in the fs field now
    means 0.001 Hz. The checklist reports it as an error, because the files are not a
    whole number of samples at that rate. No stored data changes: the database holds
    Hz.
14. **The sample type stayed as set when a new folder was chosen.** The user saw
    `int8` on a new folder. On a fresh start the tab showed `int16`. After `int8` was
    set for folder `06`, the next folder kept it, and fs was filled in for `int8`.
    Fixed by D26 after the user's decision: a new folder resets the file duration,
    the format fields, the channel rows and the RF chain rows.
15. **Unreadable fields in the dark theme.** The read-only fields took colours from
    the style's light standard palette. Under Windows dark mode they showed white text
    on light grey, and the source folder showed white text on white. The agent's
    offscreen screenshots use the light palette, so the agent did not see it. Fixed
    in `8fb5ca0`: field colours come from the current palette and follow a theme
    switch, and the checklist has a colour set for each theme. Tests check a WCAG
    contrast ratio of at least 4.5 in both themes. The offscreen platform cannot show
    the Windows 11 style in light mode on a PC set to dark mode, so the light theme is
    checked through the palette only.
16. **A channel folder can be logged as a recording.** The user's screenshot shows
    `04_short_last_file\0` chosen as the folder: one channel in the recording folder,
    relative path `0`. Nothing stops it. Not saved in the test. Question below.

### Manual test set

The agent created 13 recordings in `fixtures_out/m3-manual/` (66 MB) and an empty
database, `dev/m3.db`. All recordings use fs = 1 kS/s. After a scan the tab fills in
fs (D21) and, for folder `07`, the file duration (D22). Any fc works, for example
`145.8`. The "Expected" column comes from running every folder through the Log tab
offscreen: scan, choose a site, enter fc, and change nothing else unless the
"Settings" column says so.

Start the app in the activated venv:

```
python -m iqdm --db dev/m3.db
```

Add a site first ("Add site"). Then, for each folder: Browse, Scan folder, enter fc
for every channel, choose the site, and read the checklist. Straight after a scan the
checklist shows grey to-do lines for the site and fc (D23).

| Folder | Settings | Expected |
| --- | --- | --- |
| `01_one_channel_flat` | defaults | 1 channel in the recording folder ("(recording folder)"), 60 files, fs "1 kHz" in italics. Saves. |
| `02_two_channels` | defaults | Channels 0 and 1, 120 files. Saves. Scan it again: "Folder already logged as recording N" and "Edit existing entry". |
| `03_two_channels_gaps` | defaults | Information: channel 0 has 2 missing seconds in 1 gap; channel 1 has 7 in 2 gaps. Coverage below 100%. Saves. |
| `04_short_last_file` | defaults | Information: the last file is 2000 bytes, shorter than 4000. Saves. |
| `05_wrong_size_middle` | defaults | Error: channel 1 has a 100-byte file. Save stays disabled. |
| `06_int8_header64` | defaults first, then Sample type `int8` and Header bytes `64` | With the defaults, fs is filled in as 516 Hz and the entry would save: this is the known limit of D21. Read the information line: it names `int16` and "no header". Set `int8` and 64: fs becomes 1 kHz and the sizes still match. |
| `07_half_second_files` | defaults | File duration set to 0.5 s from the file names (information line), fs 1 kHz. Saves. Then set the duration to 1.0 by hand: errors for the file spacing and for coverage above 100%. |
| `08_unrecognised_files` | defaults | Information: 4 entries not recognised and ignored. Saves. |
| `09_error_leading_zero` | defaults | Error: "The scan stopped with 1 problem ... leading zero: 01". |
| `10_empty_channel_folder` | defaults | Error: channel 2 has no data files. A to-do line also asks for fs of channel 2 (issue 9). |
| `11_three_channels_for_edit` | defaults | Saves. Use it for the edit-mode steps below. |
| `12_one_channel_in_0_bin_float32` | defaults first, then Sample type `float32` | With the defaults, fs is filled in as 2 kHz (the D21 limit again). With `float32`, fs becomes 1 kHz. One channel in folder `0`, `.bin` files, 8.0 kB per file. Saves. |
| `13_four_channels_one_hour` | defaults | 4 channels of 3,600 files (14,400 files). Saves. The scan is too fast on a local disk to show the progress count. |

Also try: type your own fs in a channel, then change the sample type. A typed fs
stays as typed and loses its italics. A filled-in fs changes with the sample type.

Edit-mode steps with `11_three_channels_for_edit`:

1. Before saving, add RF chain rows: one for "Recording", one for "Ch 1", one for
   "Ch 2". Save.
2. After the save, the checklist reports the folder as logged. Click "Edit existing
   entry". Change the remarks and save. The message reads "Saved changes to
   recording N."
3. Change fs of one channel. The checklist asks for a rescan, and Save is disabled.
   Set fs back.
4. In Explorer, rename folder `2` to `x2`. Click "Scan folder". The "Ch 2" row leaves
   the form, and the message says so (D20). Click Save entry. The dialog names
   channel 2 and 1 RF chain parameter. Answer No: nothing is saved. Reopen the entry
   to see the stored rows again.
5. Repeat step 4 and answer Yes. Channel 2 and its row are removed.
6. Rename `x2` back to `2` and rescan. The checklist reports "The rescan adds
   channel 2" and asks for its fc. Its fs is filled in from the file size; the
   stored fs of channels 0 and 1 stays as it was.
