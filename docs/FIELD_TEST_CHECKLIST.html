IQ Data Manager: field test checklist, second visit

What the first visit on 2026-10-05 left open: locking between two PCs, reads past the PC's memory, and the legacy import with the real times. Build: dist\m7-3.

Paths in the commands. Enter the real paths here. Every command below changes to match.

The program folder is where you unzip the build: it holds IQDataManager.exe. Use the same folder on both PCs. The work folder is a new, empty folder on the laptop's own disk for the test data. The scratch share holds the scratch folder iqdm-test2. The legacy root is where the real recordings sit, as their data_dir values name it.

Bring back only text output and screenshots. Do not copy the legacy database, or any catalogue made from it, into the repository. Never point the app at the real catalogue during these tests.

Ticks and notes are kept in this browser on this PC.

1. Set up

  1. 1.1Unzip the m7-3 build into the program folder, {PROG}, on the test laptop and on a second PC (PC B).
  2. 1.2Create the work folder, {WORK}, on the laptop. It must be empty.
  3. 1.3In Explorer, create an empty scratch folder on the NAS: {SHARE}\iqdm-test2
  4. 1.4Open a Command Prompt on the laptop: 
    cd /d {PROG}

    The commands below start with the program's name, so they run from this folder.

2. Locking between two PCs

  1. 2.1Create a scratch database on the NAS: 
    IQDataManager-check.exe db-check create {SHARE}\iqdm-test2\lock.db

    every line says PASS.

  2. 2.2On the laptop, hold the database: 
    IQDataManager-check.exe db-check hold {SHARE}\iqdm-test2\lock.db --seconds 30 > {WORK}\db-hold.txt 2>&1
    Within those 30 s, on PC B: 
    {PROG}\IQDataManager-check.exe db-check write {SHARE}\iqdm-test2\lock.db > {PROG}\db-write-B.txt 2>&1

    the write waits until the hold ends, then passes. Bring back both files.

3. Reads past the PC's memory

On a 10 GbE link, reads from the NAS and reads from the PC's memory take about the same time, so a watch cannot tell them apart. The Windows counter of received bytes can.

  1. 3.1Write a new test set: 
    IQDataManager-check.exe make-test-set {WORK}\set
  2. 3.2Start the app with its own settings file: 
    IQDataManager.exe --config {WORK}\config.toml
    In the Settings tab:
    • New database... and choose {SHARE}\iqdm-test2\m7.db. Answer Yes.
    • NAS locations: add {SHARE}\iqdm-test2
    Then click Save.
  3. 3.3Log {WORK}\set\A-large-files in the Log recording tab. Archive it to {SHARE}\iqdm-test2\archive\A.

    the archive passes.

  4. 3.4In a Command Prompt, note the received bytes: 
    netstat -e
  5. 3.5In the Archive / copy tab, choose Sizes and hashes of every file, then click Check before delete on A. Do nothing else on the network while it runs.

    the check passes.

  6. 3.6Run netstat -e again.

    "after" minus "before" is at least 4,000,000,000 bytes: the 4 GB of A came over the network. A difference far below that means the reads came from the PC's memory.

  7. 3.7Optional, the copy speed with 16 files at once: 
    IQDataManager-check.exe copy-check {SHARE}\iqdm-test2\cc-A --source {WORK}\set\A-large-files --workers 1 4 8 16 --fsync on --hash > {WORK}\copy-check-A.txt 2>&1

4. Legacy import with the real times

Everything in this section writes only to {WORK}\legacy. Nothing is written to the NAS or to the legacy file.

  1. 4.1Copy the legacy database to {WORK}\legacy\legacy-copy.db, while nobody is writing to it. Check that no file named <name>-journal sits next to the original.
  2. 4.2Dry run, with the same --nas-root, --drive and --table options as on the first visit: 
    IQDataManager-check.exe migrate-legacy {WORK}\legacy\legacy-copy.db {WORK}\legacy\catalog.db --nas-root {LEGACY} --dry-run > {WORK}\legacy\dry-run.txt 2>&1

    no "cannot be read" warning for dates such as 12-Apr-2023. A row whose date and date_unix fall on different days still gets a warning.

  3. 4.3Real run on the laptop's disk: the same command without --dry-run, and without the > part, so you see the result.

    catalog.db and catalog.db.report.txt appear in {WORK}\legacy.

  4. 4.4Open the trial catalogue: 
    IQDataManager.exe --config {WORK}\legacy\config.toml --db {WORK}\legacy\catalog.db

    the Viewer lists the recordings at midnight of their day, "archived, not verified", with sizes "unknown".

  5. 4.5Check archive on each recording (about 40): select it in the Viewer, click Archive / copy, then Check archive.

    each check says the counts, sizes and times now come from the folder. The Viewer then shows the time of the first file, the size and the coverage.

    If a check says the files are some other number of seconds apart than the entry's file duration, note the recording. Its file duration needs correcting in the Log tab.

5. Bring back

  1. 5.1db-hold.txt from the laptop and db-write-B.txt from PC B.
  2. 5.2The two netstat -e numbers from steps 3.4 and 3.6, and copy-check-A.txt if you ran step 3.7.
  3. 5.3dry-run.txt and catalog.db.report.txt, and the notes of any Check archive that failed or named a file duration.
  4. 5.4A screenshot of any message that looked wrong or unclear.

6. Clean up afterwards

  1. 6.1Remove {WORK} from the laptop, and {PROG}\db-write-B.txt from PC B.
  2. 6.2Remove {SHARE}\iqdm-test2 from the NAS.
